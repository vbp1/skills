# Технический Pre-Mortem — оркестрация

Сам анализ выполняет субагент `premortem-analyst`
(`~/.claude/agents/premortem-analyst.md`) в чистом контексте: он видит только
переданный план и код проекта. Твоя работа в основном диалоге — собрать
передачу, запустить его и обработать результат.

## 1. Собери передачу (handoff)

Субагент не видит диалога. Передай ему самодостаточное описание:

- **План** — либо абсолютный путь к план-файлу (`todos/*.md`, дизайн-док),
  либо полный текст плана inline. Главное — план должен попасть к субагенту
  целиком.
- **Цель** — зачем делается изменение.
- **Правки** — список изменений и затронутые файлы/модули, насколько известно.
- **Ограничения и принятые решения** — всё существенное, что решили в
  обсуждении, но чего нет в план-файле.
- **Корень проекта** — рабочая директория.

Если план из диалога настолько неполон, что передачу не собрать, — сначала
уточни у пользователя (AskUserQuestion), не запускай субагента вслепую.

## 2. Запусти субагента

Agent tool: `subagent_type: "premortem-analyst"`, в prompt — передача целиком.
Агент уходит в фон (режима «дождаться на месте» у инструмента нет) — дождись уведомления
о его завершении и только потом продолжай; результат не додумывай.

## 3. Если вернулся блок NEED-INFO

Задай его вопросы пользователю через AskUserQuestion (переформулируй простым
языком, без внутреннего жаргона) и продолжи **того же** агента через
SendMessage, передав ответы. Нового агента не запускай — наработанный им
контекст анализа должен сохраниться.

## 4. Сохрани отчёт и покажи выжимку

- Полный отчёт (финальный текст субагента) сохрани как есть:
  - план был файлом → рядом с ним, с префиксом: `premortem-<имя-плана>.md`;
  - плана-файла нет → `premortem-<slug>.md` в `todos/` (если каталог есть)
    или в корне проекта.
- Если план был файлом — допиши в его конец строку-ссылку:
  `Pre-mortem: <относительный путь к отчёту> — <вердикт>, <дата>`.
- В диалоге покажи только: сводку, вердикт, блокирующие Тигры (с `file:line`)
  и путь к полному отчёту. Весь отчёт в диалог не вставляй.

## 5. Перепроверь исправления до GO

Триггер: вердикт круга — не `GO` (`GO с условиями` и `NO-GO` тоже запускают
перепроверку), и план поправлен по отчёту.

1. Продолжи **того же** агента через SendMessage. Нового агента не запускай.
   В сообщении передай:
   - путь к новой редакции плана (или её полный текст, если плана-файла нет);
   - путь к отчёту прошлого круга;
   - задание: по каждому риску и условию прошлого отчёта сказать, закрыт ли он
     новой редакцией (с якорем на место в плане), найти новые риски, которые
     внесли сами правки, и закончить вердиктом
     `GO / GO с условиями / NO-GO`.
2. Сохрани отчёт круга N (N ≥ 2) рядом с отчётом первого круга:
   `premortem-<имя-плана>.rN.md` (без плана-файла — `premortem-<slug>.rN.md`).
   Допиши в план строку
   `Pre-mortem, круг N: <относительный путь к отчёту> — <вердикт>, <дата>`.
3. Покажи выжимку круга по правилам шага 4.
4. Вердикт `GO` — цикл закончен. Иначе поправь план по отчёту и повтори с
   пункта 1.
5. После третьего круга без `GO` спроси пользователя через AskUserQuestion:
   ещё круг / принять оставшиеся риски / остановиться. Решение запиши в план
   строкой `Pre-mortem: решение после круга N — <решение>, <дата>`.
   «Ещё круг» — повтори с пункта 1 и спроси снова после следующего круга
   без `GO`.

## 6. Дальше

Pre-flight чек-лист из отчёта последнего круга — входные условия реализации:
перед написанием кода пройди его пункты. Блокирующие Тигры без митигации = к
реализации не приступать.
